01

一张纸，一台终端，四条命

视觉只回答一个问题：“这是我做的决定，还是别人替我做的？” 卡片是暖色的纸，背景是冷的终端；颜色只用来标记派系，不用来煽情。

四条命，四种颜色

资本金、工程绿、客户蓝、政界红。颜色只出现在仪表、标签与临界反馈里；卡面永远是纸色，把注意力留给台词。

COLOR = FACTION

纸牌 × 交易终端

卡片用新闻纸的暖色与几何肖像，界面用交易终端的黑、细线与等宽数字。两种质感对撞，就是“人”与“系统”的对抗。

PAPER × TERMINAL

别把手机放大

桌面端保持 9:16 的“舞台”比例，多出来的空间给新闻流、仪表盘与决策日志，而不是把卡片与字号拉满。

02

双端界面：手机是全部，桌面是舞台

手机上，一屏即一局；桌面上，中间永远是 9:16 的舞台，两侧承担“信息与后果”。两端看到的是同一张卡，不是两个游戏。

手机端 · 全屏竖屏

单手握持，拇指覆盖卡片下半区；滑动阈值 96px，拖动时只亮起受影响的两条线，不显示正负。安全区、底牌槽与手势条都在同一屏内解决。

  • 1财季进度：13 格 = 1 个财季，固定里程碑与它对齐。
  • 2四条命：只有图标 + 填充高度，不出现数字；临界时脉冲。
  • 3卡片拖动区：松手过阈值即确认，拖回中线取消，不可撤销。
  • 4底牌槽：4 格，第 5 张挤掉最旧，藏在拇指下方。
  • 5安全区：底部 34px + 手势条，不遮挡选项。

05

适配规则：同一套规则，三种输入

断点只决定“信息放在哪里”，不改变卡片比例、字号层级与数值规则。手机、平板、桌面共享同一套设计变量。

断点布局舞台宽度输入关键处理
≥ 1280三栏：新闻 296 / 舞台 / 仪表 312520鼠标拖拽 + ← →两侧面板常驻；舞台垂直居中，不随窗口缩放
1024–1279两栏：舞台 + 仪表480鼠标 + 键盘新闻折叠为顶部单行 ticker；日志收进抽屉
768–1023单栏舞台，两侧收成抽屉440触摸 + 键盘仪表压缩为舞台上方四条细线；底牌槽固定在舞台下沿
< 768全屏竖屏，100dvh100vw触摸滑动安全区 env(safe-area-inset-*)；底牌槽上移 34px；无横向滚动

说明：桌面端最大舞台宽度 520px，是“卡片清晰 + 两侧信息可读”的平衡点；再宽就会变成把手机放大，失去终端感。

比例优先

卡片永远是 9:16 的舞台，不做横向拉伸；宽屏多出的空间给信息面板，不给字号。

双输入等价

触摸滑动、鼠标拖拽、键盘 ← → 映射同一个动作；按钮是给键盘与辅助技术的兜底。

安全与性能

安全区内边距、44px 触控目标、100dvh；纯 CSS/SVG，无图片资源，首屏 < 100KB。

06

组件与工程规范

设计变量直接写成 CSS 自定义属性；组件只有 6 个，能拼出全部界面。颜色从不单独承载信息，图标与文字永远同时出现。

:root / DESIGN TOKENS
/* 颜色 */
--bg: #080A09;   /* 终端底 */
--paper: #F2ECDF; /* 卡片纸色 */
--ink: #17140F;   /* 纸面墨色 */
--green: #76B900; /* 主绿 · UI 强调 */
--gold: #C9A24A;  /* 资本 */
--blue: #5689DA;  /* 客户 */
--red: #D4574A;   /* 政界 / 临界 */

/* 尺度 */
--r-s: 8px; --r-m: 14px; --r-l: 22px;
--stage-max: 520px;  /* 桌面舞台 */
--wrap: 1240px;

/* 动效 */
--ease: cubic-bezier(.2,.7,.2,1);
/* 卡片 340ms · 结算 550ms · 死亡 1200ms */
